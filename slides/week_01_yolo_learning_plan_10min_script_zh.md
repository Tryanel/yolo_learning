# 《YOLO 第一周学习计划》10 分钟中文讲稿

## 假设
- 听众：刚开始学习 YOLO/目标检测的初学者，主要使用 Windows + PowerShell。
- 场景：Week 01 课程导入或学习计划说明。
- 目标时长：10 分钟。
- 语气：清晰、稳、少焦虑，强调可复现和每天小闭环。

- Slide 1：0:50
- Slide 2：1:25
- Slide 3：1:20
- Slide 4：1:30

## 开场
大家好，这一节我们进入 YOLO Learning Lab 的第一周。第一周的重点不是马上训练出一个模型，也不是追求炫酷的摄像头实时识别，而是先把学习环境稳定下来。  

如果环境不稳定，后面每一次训练、推理、排错都会变成猜谜。所以我们这一周要做的事情很朴素：让仓库、Python 环境、依赖安装和检查脚本进入一个可控、可复现的状态。每天只需要 45 到 60 分钟，目标是小步跑通，而不是一次性吃完所有内容。

## Slide 1：WEEK 01
- 目标：建立第一周的学习基调，降低学习焦虑。
- 时间：0:50
- 讲稿：
这一页是第一周的总览。我们这周的主题叫“本地轻量环境”。请注意这里的关键词是“轻量”和“稳定”。  

这一周不是让本地电脑承担模型训练任务，尤其如果电脑配置一般，更不应该一开始就把它当成训练服务器。我们只需要让它成为一个学习工作台：能打开仓库，能创建虚拟环境，能运行检查脚本，能保存输出记录。  

这里列出的命令，比如创建 `.venv`、激活虚拟环境、运行 `scripts/check_environment.py`，都是为了确认我们后面的学习有一个可靠起点。
- 转场：
明确了第一周的大方向之后，我们来看这一周到底只解决哪一件事。
- 讲者提示：
强调“本周目标不是训练模型”。这里要让学习者先放下产出模型的压力。

## Slide 2：这一周只解决一件事：本地能稳定学习
- 目标：解释本周范围，以及哪些事情暂时不做。
- 时间：1:25
- 讲稿：
这一周我们只解决一件事：本地能稳定学习。  

“稳定学习”具体包括三层。第一，装对 Python。这里特别要确认不是 Windows Store 的占位入口，而是能看到真实版本号和真实安装路径。第二，建立虚拟环境。虚拟环境的作用是把 YOLO 学习需要的依赖和系统环境隔离开，后面如果装错了、版本冲突了，也更容易重来。第三，跑检查脚本，把 Python、Torch、Ultralytics、CUDA 或硬件状态记录下来。  

这一周我们不追求三件事：不训练自定义模型，不做实时摄像头推理，也不部署在线服务。它们都很重要，但不是第一周要硬做的事情。训练和部署会从后面的周次逐步交给 Colab、Ultralytics Platform 或 Hugging Face Spaces。
- 转场：
既然本地不负责重训练，那么本地和云端到底应该怎样分工？下一页我们把边界讲清楚。
- 讲者提示：
可以停顿一下提醒：“暂时不做，不代表不重要，而是顺序要对。”

## Slide 3：本地与云端的分工
- 目标：建立学习系统的边界感，避免把弱电脑推向重任务。
- 时间：1:20
- 讲稿：
这一页讲本地和云端的分工。第一周我们先把左边做好，也就是本地电脑这一侧。  

本地电脑最适合做四类事情：仓库管理，比如 README、notes、assignments；轻量预测，比如少量图片和 nano 模型；数据整理，比如图片归档和 `dataset.yaml`；以及复盘记录，比如错误案例和环境日志。  

右侧这些云端资源，是未来会用到的。比如模型训练可以放到 Colab 或 Ultralytics Cloud，批量评估可以用验证集、mAP 和错误案例来做，在线 Demo 可以放到 Hugging Face Spaces 或 Roboflow，模型导出则可能涉及 ONNX、API 或托管推理。  

第一周先完成本地侧闭环。我们要知道云端未来会接什么任务，但这一周不急着把训练和部署都做完。
- 转场：
边界清楚以后，我们就可以把第一周拆成 7 个小任务，每天完成一个可保存的证据。
- 讲者提示：
这里可以用“左边先闭环，右边先认识”来帮助记忆。

## Slide 4：7 天安排：每天一个小闭环
- 目标：让学习者知道每天做什么，以及每天的可交付证据。
- 时间：1:30
- 讲稿：
接下来是第一周的 7 天安排。设计原则很简单：每天只留一个主任务，结束的时候都要有一个可保存的证据。  

第一天确认 Python，重点看版本号和安装路径。第二天创建虚拟环境，确认 `.venv` 可以激活。第三天安装依赖，确保 `requirements.txt` 能跑完。第四天运行环境检查脚本，并保存输出记录。第五天认识仓库结构，知道 README、notes、assignments、scripts 这些文件分别放在哪里。第六天补最小 Python，只学变量、函数、路径、参数这些能读懂脚本入口的内容。第七天做复盘与排错，写出 `notes/week_01.md`。  

节奏上，每天 45 到 60 分钟就够了。遇到安装问题时，不要马上跳到训练，也不要反复复制随机命令。先记录现象、命令和输出，这个记录本身就是第一周的重要产物。
- 转场：
这 7 天里，最关键、最容易卡住的就是环境搭建命令。下一页我们把命令按顺序讲一遍。
- 讲者提示：
这一页适合提醒学生：每天结束前必须留下些什么，不能只凭感觉说“我学过了”。

## Slide 5：环境搭建命令：一行一行跑
- 目标：讲清楚 PowerShell 中的执行顺序和常见判断点。
- 时间：1:35
- 讲稿：
这一页是第一周最重要的操作页。请一定按顺序一行一行跑，不要跳步。  

第一步，运行 `python --version`，先确认能看到 Python 版本号。然后运行 `where.exe python`，看 Python 到底从哪里启动。如果只看到 WindowsApps 路径，很可能还是 Windows Store 的占位入口，需要先修正 Python 安装。  

第二步，运行 `python -m venv .venv` 创建虚拟环境。然后用 `.\.venv\Scripts\Activate.ps1` 激活它。判断是否激活成功的方法很简单：命令行前面出现 `(.venv)`，再继续安装依赖。  

第三步，升级 pip，然后运行 `pip install -r requirements.txt`。最后运行 `python scripts/check_environment.py`。检查结果不要只看一眼就关掉，要复制到 `notes/week_01.md`。  

如果这一页跑不通，也没关系。第一周不是比谁环境一次成功，而是学会把问题记录清楚：执行了什么命令，看到什么输出，下一步准备怎么排查。
- 转场：
命令跑起来以后，我们还需要一点点 Python 基础，但这个基础不需要学得很深。
- 讲者提示：
读命令时放慢语速。强调“先确认入口，再建隔离环境，最后跑检查脚本”。

## Slide 6：够用的 Python：只学会读懂脚本入口
- 目标：限定 Python 学习范围，避免初学者陷入算法或语法细节。
- 时间：1:15
- 讲稿：
第一周的 Python 要求非常克制：不学算法，不追求写复杂程序，只补能运行脚本、改参数、看路径的能力。  

比如看到 `model_path = "yolo11n.pt"`，你知道这是一个变量，里面保存了模型路径。看到 `def main():`，你知道这是脚本的主入口。看到 `classes = ["phone", "cup"]`，你知道这是一个列表。看到 `metrics = {"map50": 0.72}`，你知道这是一个字典。看到 `Path('data/samples')`，你知道这是在处理路径。看到 `argparse.ArgumentParser()`，你知道这是命令行参数。  

检查自己是否够用的标准也很简单：能打开 `scripts/check_environment.py`，大概说出每一段在检查什么，就达标了。第一周不需要把 Python 学成一门完整课程。
- 转场：
有了环境和最小 Python 识读能力之后，本周最后要交付的不是模型，而是一份环境证据。
- 讲者提示：
这里要安抚初学者：不会 Python 全套语法也可以继续学 YOLO，先掌握读脚本入口。

## Slide 7：本周作业：交付环境证据
- 目标：定义作业内容和通过标准。
- 时间：1:10
- 讲稿：
本周作业很明确：不交模型文件，交一份能复盘的环境记录。  

第一步，运行 `python scripts/check_environment.py`。第二步，保存关键输出，包括 Python、Torch、Ultralytics、CUDA 等信息。第三步，写学习复盘，放到 `notes/week_01.md`。第四步，列出阻塞问题，包括错误信息、已经尝试过的命令、以及你认为下一步应该怎么查。  

通过标准不是“没有报错”，而是你能解释虚拟环境的作用，也知道当前电脑适合本地轻量测试，还是更适合把训练交给云端。  

换句话说，第一周的核心能力是：能把环境状态讲清楚，能把问题记录清楚，能为第二周继续学习留下可靠入口。
- 转场：
最后，我们用一页完成定义来确认：第一周结束时，到底怎样算完成。
- 讲者提示：
强调“问题记录不是失败，而是交付物”。这句话对降低挫败感很有用。

## Slide 8：完成定义
- 目标：收束第一周成果，并引出第二周。
- 时间：0:55
- 讲稿：
第一周结束时，你不需要有模型成果。你只需要有三样东西：一个可复现的学习环境，一份环境记录，以及继续进入第二周的信心。  

具体检查项包括：Python 入口正确，`.venv` 可以激活，依赖安装有记录，`check_environment.py` 已经运行，`notes/week_01.md` 已经写好。  

下一周我们会进入目标检测基础，开始理解 bounding box、confidence、IoU、mAP，以及模型为什么会漏检或误检。  

所以第一周的任务不是冲刺，而是打地基。只要你能把本地环境稳定下来，并且把每一步记录清楚，就已经准备好进入 Week 02。
- 转场：
到这里，第一周学习计划说明结束。接下来可以进入实际操作，先从 `python --version` 和 `where.exe python` 开始。
- 讲者提示：
结尾要给确定感：完成定义不是模糊的“学会”，而是五个可检查的勾选项。

## 结尾话术
今天这 10 分钟，我们只做了一件事：把第一周的学习目标从“我要赶紧训练模型”，调整成“我要先建立一个可复现、可排错、可继续学习的本地环境”。  

接下来请按 7 天安排推进。每天只做一个小闭环，每天都留下证据。等这些基础跑稳以后，后面的目标检测概念、模型训练和部署才会变得顺畅。
